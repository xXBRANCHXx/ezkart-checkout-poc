# Shared storefront cart

Ezkart templates use one shared cart entry point outside the page navigation.
The standard control is a floating shopping-bag icon, **Cart** label and item
count in the bottom-right corner. Its neutral white surface stays recognizable
across different storefront palettes. Keep the empty state accessible too.

## Behavior

- Product buttons, variant controls and repeated placements use the existing
  catalog bindings and shared cart. Templates do not implement their own cart.
- Adding a product opens the shared drawer with that variant, quantity and price.
- The floating control stays clear of fixed purchase bars, ordinary catalog purchase buttons, variant selectors, and device safe areas.
- Desktop uses a right-side drawer; mobile uses the full available width.
- Closing the drawer preserves the cart and returns focus to the opener.
  Escape, Tab and Shift+Tab work throughout the drawer.
- Quantity and subtotal changes update the same cart count everywhere. Checkout
  follows the store's existing checkout flow; local fictional concepts use the
  explicitly configured simulated checkout.

For new templates, leave the shared floating control in place and omit a second
cart control from the navigation. Existing merchant-authored cart controls remain
supported. Purchase bars may provide a contextual add action; they must not cover
the shared cart or introduce a second drawer.

Verify empty/populated states, variants, quantity limits, close/reopen, keyboard
focus, and purchase-bar overlap in the real Preview and exported storefront.

## Add-to-cart code for custom HTML

In **Products**, open a product's **⋯ → Copy add-to-cart code**. Choose an
available variant, quantity and link text, then copy the generated HTML. The code
contains catalog identifiers, never a supplied price. Current stock is checked
again when copying and by checkout when the customer follows the link.

```html
<a class="ezkart-add-to-cart"
   href="https://YOUR_EZKART_HOST/cart/?shop=YOUR_STORE&amp;add=PRODUCT_ID~VARIANT_ID:1"
   data-ezkart-add="PRODUCT_ID"
   data-ezkart-variant="VARIANT_ID"
   data-ezkart-quantity="1">Add to cart</a>
```

Use the actual URL generated by the product menu. Omit the variant attribute and
`~VARIANT_ID` for products without variants. Keep the `href` when changing the
markup or styling: it makes the link work on any HTML site, without an external
JavaScript dependency. It opens the hosted Ezkart cart and merges the specified
quantity into that store's cart. Reloading the cart does not add it a second time.

On an Ezkart-generated page, the same attributes open the standard floating cart
drawer when the product is connected to that page. Both anchors and buttons are
supported, including dynamically inserted controls and nested images or text.
The runtime preserves custom content; CSS can style the control freely. Products
outside the page's bound catalog use the anchor's hosted-cart fallback.

Custom JavaScript on a page that includes Ezkart's storefront runtime can call:

```js
const added = EzkartCart.add({
  productId: "PRODUCT_ID",
  variantId: "VARIANT_ID", // omit for a product without variants
  quantity: 1,
});
```

`add` returns `true` and opens the shared drawer on success. It returns `false`
for an unknown product/variant, invalid quantity, or a quantity exceeding stock.
It never accepts a custom price. `EzkartCart.open()` opens the shared drawer.
The API is supplied by Ezkart storefront output; ordinary external HTML uses the
portable anchor above. Templates continue to use native commerce elements.
